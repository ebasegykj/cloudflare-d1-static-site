# 站点数据标准（SITE-STANDARD）

> 背景：这个模板是从一个跑了很久的真实站点上抽出来的。原站点后来接了第二个站，数据语义差异
> 散落在代码各处、靠人肉对照，于是接连踩了「漏登记暂存标记」「CRLF 假差异」「备份撞 50
> 子请求上限」几个坑。根因都一样：**差异没有唯一的登记处**。
>
> 这份文档把差异收拢成**三个合法位置**，其余一律视为 bug。
> 模板本身是**单站**的——只有你打算用同一套后端再挂第二个站点时，本文才真正开始起作用。

## 原则

一套后端 = 一个 worker + 一套 Pages Functions + 一套 admin 接入方式 + 一套测试。
前端风格、页面数量、数据组织方式可以随站点不同，但**所有数据语义差异必须集中登记**，
不允许"这里特判一下"散落在各个函数里。

判断某段代码该不该存在，只问一句：**它是不是在描述"某个站的数据长什么样"？**
是 → 属于登记处；不是 → 属于通用逻辑。

## 差异只允许出现在这三个位置

### 1. worker 的站点规格注册表（`wecom-worker/worker.js` 顶部 `SITE_SPEC`）

```js
const SITE_SPEC = {
  main: { dbVar: 'DB', manifest: 'data-import.json', dataDelRe: /^data\// },
};
const specOf = () => SITE_SPEC.main;
```

| 字段 | 作用 |
|---|---|
| `dbVar` | D1 绑定变量名。改了要同步 `wrangler.toml` / CF 后台的绑定名 |
| `manifest` | 导入快照文件名（`tools/gen-import.mjs` 的产物） |
| `dataDelRe` | 备份分支"删除同步"只认这些路径。**范围给宽了会删代码** |

改这里 = 导入/备份/删除同步/数据源切换等全部运维命令自动跟随，不用改任何调用点。
模板里 `specOf()` 不收参数、恒返回 `main`，是为了保持调用点形态不变（单站也走同一条路径）。

### 2. Pages Functions 的数据路径白名单（镜像契约）

- `functions/data/[[path]].js` —— 只接管 `/data/*` 的读取，按旧格式逐字节输出
- `_routes.json` —— `{"include":["/data/*"]}`，其余路径保持纯静态（免费额度不受影响）

这两处是**同一个契约的两面**：Function 决定"接管什么"，`_routes.json` 决定"路由到不到它"。
改一边必须改另一边。**其余路径一律纯静态，不要图省事把 `/` 塞进 include。**

### 3. 界面文案（帮助文本、提示语、按钮文字）

`HELP` 段落、各命令的回话措辞、后台页面的提示语——不影响数据语义，随便改。
这是唯一"改了不需要同步任何地方"的位置。

## 纪律（血泪坑，违反必复发）

1. **新增暂存标记必须登记 flush 跳过清单。**
   `flushPending` 开头有个通用循环：标记不在跳过清单里就当文件路径去读 `data/<标记>.js`。
   漏登记 → 文件不存在 → 整批发布失败（现象是"找不到 `data/xxx.js`"）。
   "删"类操作必须配端到端用例，不能只测"加"。
2. **换行符归一。**
   仓库 `.gitattributes` 是 `* text=auto`（存 LF）。任何"读工作区文件写进 D1/快照"的脚本，
   读进来先 `.replace(/\r\n/g, '\n')`。Windows 下 `autocrlf` 不归一 → 每个文件都是"假差异"
   → 备份/导入变成全量。
3. **批处理要限批。**
   免费版单次 Worker 调用最多 50 次子请求。循环里发 fetch 的任务必须限批（备份每批 30 个
   blob）+ KV 游标续传，并把"还要再发一次"写进回执。
4. **后台任务结果必须落 KV。**
   主动推送受企业微信可信 IP 白名单限制，会静默失败（`errcode 60020`）。
   `waitUntil` 里跑完的任务，结果同时写 `bkres:<user>` 之类的键，并配一条查询命令。

## 如果真的要加第二个站点

模板已经单站化，加站是**破坏性改造**，按下面顺序做，一步都别跳：

1. CF 建第二套 D1 库，worker 绑定 `DB_<站名>`；CF 变量里加 `SITES` 条目
   （含 `KV_PREFIX`——KV 前缀隔离是分库之外的第二道墙，必配）；
2. worker：`SITE_SPEC` 加一条；把 `specOf()` 改成按路径取（单站版故意忽略参数）；
   bot 侧按 `SITES` 路径合并环境（发文字段 / HELP 文案）；
3. 仓库：Functions 镜像文件 + `_routes.json`（**对照现有站点逐行核对**）；
4. admin：照现有站点的 D1 模式补丁（Worker 地址 + `ADMIN_KEY` + 测试连接）；
5. 测试：`test.mjs` 必须补"分库污染"用例——新站操作不得写主站库；
6. 首次「导入D1」后必跑「核对D1」，再跑黄金样本比对（线上 vs 仓库 HEAD 逐字节），
   然后才允许首次「备份D1」、删除仓库数据目录。

> 第 1 条最容易漏：**没绑库的第二站点绝不能继承主站的 `env.DB`**，否则数据会串站。
> 单站模板下这条不会发生，加站时它是第一优先级。
